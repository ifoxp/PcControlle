# PC Control — мобільний пульт (Flet, Android)

Динамічний «пульт ПК»: сітка команд 4-в-ширину, яка **будується з `/manifest`**.
Нова команда на ПК → кнопка «Оновити» в додатку → нова плитка. Додаток не треба
перевидавати.

## Як це працює

1. **Парування.** На ПК: *Панель → Пристрої* показує QR (host+port+PIN+fingerprint).
   У додатку встав код QR (або введи вручну) → додаток шле `POST /pair` за PIN →
   отримує **per-device Bearer-токен** і зберігає ПК.
2. **TLS-pinning.** Додаток довіряє серверу не через публічний CA, а звіряючи
   **SHA-256 fingerprint** сертифіката (з QR). MITM неможливий.
3. **Динамічна сітка.** `GET /manifest` віддає список команд із типом віджета.
   Додаток малює плитки; кожен тип має вбудовану реалізацію.

## Типи віджетів (вбудовані)

| widget | Поведінка |
|--------|-----------|
| `button` | тап → запит (небезпечні — з підтвердженням) |
| `toggle` | перемикач (сервер сам змінює стан) |
| `slider` | качелька (гучність…), початкове значення через `getter` |
| `media_view` | відповідь-зображення → перегляд zoom/pan + **Поділитися** + **Зберегти в Downloads** |
| `audio` | відповідь-аудіо → програвач + поділитися/зберегти |
| `text_input` | поле вводу + виконати (напр. URL, таймер) |
| `picker` | вибір з варіантів (напр. гарячі клавіші) |

## Структура

```
main.py                 ← точка входу + роутинг екранів
theme.py                ← єдина тема (темна) + хелпери Flet 0.85
core/
├─ api_client.py        ← HTTP-клієнт: TLS-pinning + Bearer + retry
├─ storage.py           ← збереження ПК/токенів (JSON у app-data)
└─ pairing.py           ← парсинг QR-даних
screens/
├─ pair_screen.py       ← підключення ПК (код QR / вручну)
├─ grid_screen.py       ← головна сітка 4-в-ширину
└─ pcs_screen.py        ← «Мої ПК» (перемикання/видалення)
widgets/                ← реалізації типів віджетів (по файлу)
```

## Запуск (розробка, desktop)

```powershell
python -m venv .venv
.venv\Scripts\python -m pip install -r requirements.txt
.venv\Scripts\flet run main.py
```

## Збірка APK (Android)

```powershell
.venv\Scripts\flet build apk
```
APK з'явиться в `build/apk/`. Потрібні Flutter SDK + Android SDK (flet підкаже,
якщо чогось бракує).

> **Перше підключення:** на ПК має бути запущений PC Control, а телефон —
> у тій самій мережі АБО ПК доступний ззовні (проброс порту на білий IP).

## ⚠️ ВАЖЛИВО: сірі екрани на Flet-Android (як діагностувати й уникати)

Під час розробки ми довго боролися з **сірим/чорним екраном** на Android (додаток
стартує, але UI не малюється). Ось повний чек-ліст причин і як їх уникати —
**прочитай перед додаванням нового екрану/віджета.**

### Головне правило діагностики
На Android `print`/traceback Python **не видно** у звичайному logcat. Тому:
1. `main.py` має `_error_view(page, where, exc)` — він **малює traceback на екрані**
   замість німого сірого. Будь-яку нову ініціалізацію обгортай у try/except із
   викликом `_error_view`. Саме він викрив головний баг (`NameError`).
2. Реальний краш ловиться через `adb logcat` по PID процесу:
   `adb logcat -d --pid=$(adb shell pidof com.shramix.pc_control_remote)`.
3. Скрін екрану телефона: `adb exec-out screencap -p > s.png` — швидко видно стан.
4. Бінарний пошук: якщо не знаєш, що ламає — зроби мінімальний `main` з
   `page.add(ft.Text("OK"))`, переконайся що працює, і додавай по одному елементу.

### Контроли/патерни, що ЛАМАЮТЬ рендер на Flet-Android (уникати!)
| Проблема | Замість цього |
|---|---|
| `NavigationBar` всередині `Column` | `page.navigation_bar = ft.NavigationBar(...)` |
| **Вкладені** `SafeArea` (одна в одній) | одна SafeArea, або відступ через `padding` |
| `SafeArea` навколо контейнера з внутрішнім `scroll`+`expand` | top-`padding` (напр. `top=50`) |
| `ExpansionTile` | звичайні поля/секції завжди видимі |
| Великий `AlertDialog` з фікс. width/height + `InteractiveViewer` | `page.overlay` (повноекранний контейнер) |
| 8-значний hex з альфою (`"#ff5a5a55"`) | звичайний 6-значний hex |
| `aspect_ratio` на плитці всередині `GridView` | не задавати, керувати через `runs_count` |
| Контейнери-«пружини» (`Container(expand=True)`) для вирівнювання | `Column(alignment=...)` |
| `page.controls = [x]` | `page.controls.clear(); page.add(x)` |

### Патерни ЗАПУСКУ (критичні)
- **`ft.run(main)` на ТОП-РІВНІ** файлу, БЕЗ `if __name__ == "__main__"`.
  serious_python **імпортує** `main` як модуль (`__name__` != `"__main__"`), тож
  під guard-ом `ft.run` не викликається → сірий екран.
- **Жодного `await` до першого рендеру.** `page.storage_paths.*` async-виклики
  можуть зависнути назавжди («Working…»). Тека стану — синхронно через `os`.
- **Імпорти важких залежностей — ліниві.** `import httpx`/`import ssl` на рівні
  модуля вішали старт (проблемний `_ssl` у бандлі). Імпортуй їх усередині функцій,
  які реально роблять мережу.
- **Класи мають свій `import theme`** (та інші модулі), якщо використовують їх —
  при лінивих імпортах у `main()` вони не видимі в класах. Головний баг сірого
  екрану був саме `NameError: theme` у `_MainShell`.
- **Мережу/потоки — у `did_mount`, не в `__init__`.** `page.run_thread` до
  монтування контролу кидає помилку.
